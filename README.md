# CardioLens — Trust-Aware 3D Cardiovascular Risk Visualization

CardioLens is an educational research prototype with a React/Three.js dashboard and a FastAPI service. It estimates CAD, LAD, LCX, and RCA model outputs from entered demographic, symptom, laboratory, ECG, and echo features. Its anatomy is a procedural explanatory visualization, not patient-specific imaging. It is not clinically validated and is not a medical device or diagnosis.

## Dataset and model status

`data/z_alizadeh_sani_dataset.csv` contains 303 records and the expected 54-column schema. It is **synthetic**: comparing every row with `generate_synthetic_records(303, 42)` reproduces the file exactly. The UCI name in the filename does not establish authenticity. The original file is retained and is never overwritten by training. The training loader currently accepts CSV only and requires explicit CAD, LAD, LCX, and RCA columns; it does not ingest the supplied Excel workbook. `CardioPreprocessor.extract_dataset()` can parse the verified extension-style `Cath` overall label when CAD is absent and maps `Stenotic` to the positive vessel class, but that parser support alone does not validate provenance, adjudicate conflicting labels, or make the current fixed feature schema compatible. Do not train from the supplied workbook until those items are resolved.

The checked-in model manifest associates the model files with the same synthetic CSV hash. This project-generated, unsigned metadata is not independent proof of historical training. `models/metrics.json` is regenerated by training and records synthetic status, target distributions, fold-local validation metrics, and excluded leakage columns. Metrics from this small synthetic cohort do not establish clinical performance or generalization.

## Requirements and startup (Windows PowerShell)

Use Python 3.10+ and Node.js 18+.

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r backend\requirements.txt
python -m pytest backend\tests -q
cd frontend
npm ci
npm run build
cd ..
python -m backend.app.main
```

Open `http://127.0.0.1:8000`. FastAPI serves `frontend/dist` when that build exists. For development, use two terminals: run `python -m backend.app.main`, then `cd frontend; npm run dev`; Vite proxies API routes to port 8000.

macOS/Linux equivalent:

```bash
python3 -m venv .venv && source .venv/bin/activate
python -m pip install -r backend/requirements.txt
python -m pytest backend/tests -q
cd frontend && npm ci && npm run build && cd ..
python -m backend.app.main
```

## Training

```powershell
python -m ml.train
```

Training uses the existing CSV as-is, fits imputers/scalers/encoders within each stratified CV training fold, selects among Random Forest, HistGradientBoosting, and Logistic Regression independently per target, then fits the chosen production estimator and preprocessing artifact on all rows. It refuses to overwrite data and errors if the dataset is missing. To create synthetic training rows explicitly when no CSV exists, call `train_pipeline(demo=True)` from Python; demo mode is never silently selected.

`CAD`, `Cath`, `LAD`, `LCX`, and `RCA` are excluded from features after alias normalization. The reported weighted overall risk (35% CAD + 30% LAD + 15% LCX + 20% RCA) is an experimental aggregation, not a validated clinical score.

## TrustMap, scenarios, and integrity

The anatomy maps model outputs across whole named vessels only. Probability bands/colors are interface conventions, not medical thresholds, and the 3D model cannot locate lesions or show patient-specific anatomy. Predictions include evidence, data-quality, calibration, and out-of-distribution status; calibration and OOD detection are explicitly reported as not evaluated.

The interactive 3D viewer uses a generic AI-assisted cutaway heart reference mesh with separate schematic, selectable LAD, LCX, and RCA overlays. The source asset is CC0; see [docs/HEART_3D_IMPLEMENTATION.md](docs/HEART_3D_IMPLEMENTATION.md) for source, anatomy, controls, implementation details, and verification limits. Drag to rotate, use the view selector to inspect anterior/posterior/left/right/superior views, and use the anatomy selector to focus a model target or structure description.

The **What-If Scenario** panel compares the current form with a separate hypothetical copy by calling the backend `/scenario` endpoint. It displays returned CAD/LAD/LCX/RCA probabilities and percentage-point differences, then updates the 3D view with the hypothetical response. This comparison is not causal or a treatment estimate. The **Integrity Passport** reads generated data/model manifests and evaluation metrics from the backend.

## API

- `GET /health`, `/model-info`, `/metadata`, `/metrics`, `/model/metrics`, `/features`, `/sample-patient`
- `POST /predict`, `/explain`, `/scenario`, `/batch-predict`

Prediction requests must supply every clinical feature shown in the form. Only BMI and Obesity may be omitted; the service derives those from the supplied height and weight. Missing required values are rejected with HTTP 422 instead of filled with invented defaults.

When the complete model artifacts cannot load, prediction, explanation, and sample-patient requests return HTTP 503 with an explanation; the backend does not synthesize replacement predictions. The health endpoint reports a degraded state. Example presets are synthetic examples and are run through the loaded models.

## Known limitations and safety

- The bundled dataset is synthetic despite its UCI-style filename and schema.
- Validation metrics are pooled out-of-fold synthetic-data demonstration results; candidates were selected using the same pooled F1 estimates. No independent held-out, external validation, calibrated probability, or prospective evaluation has been established.
- Explainability uses target-specific SHAP values relative to a deterministic synthetic reference subset. Units depend on estimator output; attribution is neither causal inference nor clinical evidence.
- The browser starts with a clearly labelled synthetic example profile. API requests reject missing features, but validation cannot establish clinical measurement quality or provenance.
- The visualization is procedural and explanatory; it does not represent a patient's actual coronary anatomy.
- Predictions and risk categories must not guide care. Consult qualified clinicians and validated diagnostic methods.

If the UI reports a connection error, start the backend first and confirm `GET http://127.0.0.1:8000/health`. If model artifacts are missing or incompatible, run `python -m ml.train` only with the included synthetic demonstration dataset or a deliberately supplied dataset whose provenance, license, label definitions, and required CSV schema have been verified. The supplied Extension workbook is not currently a supported training input. Missing artifacts cause inference to abstain; no fallback scores are generated.
