# CardioLens Technical Report

**Multimodal AI Hackathon 2026 - Track A: Cardiovascular Risk Visualization & Prediction**  
**Data disclosure:** All bundled data, labels, model training, and reported metrics in this prototype are synthetic demonstrations. They are not clinical performance estimates.

## 1. Problem and proposed solution

CardioLens is an educational prototype combining a React/TypeScript dashboard, FastAPI inference service, four tabular classifiers, target-specific SHAP explanations, an API-backed what-if comparison, and a procedural Three.js coronary anatomy. It returns separate CAD, LAD, LCX, and RCA model outputs. It does not diagnose disease or generate patient-specific imaging.

## 2. Data and provenance

These are not population estimates.

The model manifest has the same dataset hash and its model/preprocessor hashes match the present files. The manifest is unsigned project metadata, not independent proof of historical training. Genuine-data training was not performed; saved model artifacts were preserved.

## 3. Preprocessing and leakage prevention

Numerical median imputation/scaling and categorical mode imputation/one-hot encoding are fit within stratified CV training folds. `CAD`, `Cath`, `LAD`, `LCX`, and `RCA` are excluded from model predictors; API validation rejects unexpected keys. The selected estimator and preprocessing artifact are fit on all 303 rows for demo inference. Clinical review of derived or post-diagnosis fields and patient-level grouping is not possible without an authentic source dictionary and identifiers.

## 4. Models and evaluation

Random Forest, Gradient Boosting, and Logistic Regression candidates are evaluated separately per binary target. Candidate selection uses pooled out-of-fold F1 from stratified five-fold cross-validation. The reported pooled out-of-fold predictions are also used for selection, which can make the metrics optimistic. No locked independent test set, external validation, calibration study, or confidence intervals are available. Brier scores are descriptive scores, not proof of calibration.

## 5. Visualization and explanations

The 3D view is procedural and schematic. Rotation, zoom, reset, and target selection display whole-vessel model outputs; the display does not locate plaque, represent patient-specific vessel geometry, or encode clinically validated severity thresholds.

Each target's saved estimator is explained separately using SHAP against a deterministic subset of up to 32 rows from the bundled synthetic cohort. SHAP values describe the fitted model output relative to that background; output units vary by estimator. Values are associations, not causal effects, clinical evidence, or proof that changing a feature changes disease. If SHAP fails, the API returns an unavailable response rather than invented values.

## 6. Limitations, safety, and future work

There is no verified clinical data source or license, independent test cohort, external validation, calibrated probabilities, uncertainty intervals, tested OOD detector, or clinical label review. Browser walkthrough, WebGL/device/accessibility checks, and live loopback network verification were not performed in this audit. There is no automated frontend unit or browser E2E suite. The prototype is for education and software demonstration only and must not guide care. Future work requires authorized genuine data, verified label semantics, source-documented predictor timing, locked independent evaluation, calibration analysis, usability/accessibility testing, and a validated imaging pipeline before patient-specific visualization claims.

The supplied Track A statement requires a 3-10-minute YouTube demonstration. The project has a demo script but no recording or YouTube URL; the full submission is not ready until that deliverable exists.

## Reproduction

From the repository root, install Python dependencies using `python -m pip install -r backend\requirements.txt`, run backend tests with `python -m pytest backend\tests -q -p no:cacheprovider`, and build the frontend from `frontend/` with `npm ci` then `npm run build`. Startup instructions and API routes are in `README.md` and `docs/API.md`. Exact release results are in `reports/final_audit/test_results.md`.
